# DNN Manager 2.0.0

**DNN Manager, rebuilt for every system.** The whole app is rewritten with the pages and actions you know from 1.8,
comes as an installer for Windows, macOS and Linux, and adds **Source Control** to send a project's files to its
servers and back.

## Highlights

### The app you know, rebuilt
- **Projects**, a project's details, **New project**, **Settings** and **Troubleshoot** work as in 1.8: start, stop
  and restart sites, keep them warm, clone, back up, restore, upgrade DNN, rename, edit host names and app pools,
  change the database connection, and remove a site.
- The window is laid out as VS Code's: the pages in the **activity bar**, a page's own view in the **primary side
  bar** (**Ctrl+B** hides it), and **Output**, **Logs** and **Terminal** in the bottom panel.
- The command palette (**Ctrl+Shift+P**), the guided tour and **Help** (**F1**) are there, and **Settings →
  Keyboard shortcuts** lets you change the shortcut of any command.
- An imported site keeps its live addresses as other aliases beside the local one, for every portal; **Clone** and
  **Rename** move the local ones, and **Export → For deployment** makes the live address primary again.

### Source Control: send files to a server and back
- **Source Control** (**Ctrl+3**) compares a project's files with a server's over SFTP, FTPS or FTP, as VS Code's
  Source Control lists changes: **Conflicts**, **Staged Changes**, **Changes** and **Server changes**, each file
  with its icon, its folder and its letter.
- **…** → **Add server…** sets up a server as FileZilla's Site Manager does. A server isn't tied to a project: every
  project can use every server and keeps its own comparison and history with it.
- Stage files with **+** and press **Commit** to upload them in one go; **Download** takes the server's copy. A
  conflict is settled with **Keep mine**, **Keep the server's** or **Merge…**.
- Click a file to compare the server's copy with yours side by side, or **Inline**, in syntax colours with the
  changed words marked. Files open in tabs, as in VS Code.
- Nothing on a server is replaced or deleted unseen: a preview lists every file before **Deploy**, `web.config`,
  `bin/`, `App_Data/` and `Portals/` are asked about again, and the server's copy can be backed up first.

### An installer for every system
- Windows: `DnnManager-windows-x86_64.msi` and `DnnManager-windows-arm64.msi`.
- macOS: `DnnManager-macos-arm64.dmg` (Apple Silicon) and `DnnManager-macos-x86_64.dmg` (Intel) - open it and drag
  **DNN Manager** to Applications.
- Linux: `DnnManager-linux-amd64.deb` and `DnnManager-linux-arm64.deb`, for Ubuntu 22.04, Debian 12, Linux Mint 21 or
  newer.
- `SHA256SUMS.txt` lists each file's checksum.

### At home on macOS and Linux
- **Projects** lists the DNN sites in your projects folder (`~/DNN` unless you choose another), with their DNN
  version and database, as **Folder - no IIS**. Making and running sites needs IIS, which only Windows has.
- Shortcuts use **⌘** on a Mac, and DNN Manager has a menu bar there.
- The status bar shows memory, processor use and disk space on every system.

### Keyboard and text fields
- **Tab** and **Shift+Tab** go through the whole window; menus, selects and the projects list work with the arrow
  keys, **Enter** and **Esc**.
- Text fields edit like your system's own: undo and redo, word moves, double-click to select a word, and a
  right-click menu.
- Every password box has an eye button that shows what you typed.

## Other changes
- Passwords are kept in your system's secure store: the Windows Credential Manager, the macOS Keychain or the Linux
  keyring. The SA password in the settings is encrypted with a key kept there.
- **Check for Updates…** (the gear menu) tells you when a newer release is out.
- Icons are drawn by DNN Manager itself, so they look the same on every system.
- A host name added in **Edit host names** is saved to the site's bindings at once.

## Upgrading
Install the new package over the old one: the .msi on Windows, the .dmg on macOS, the .deb on Linux. Your settings
keep their format.
- From 1.8: **Update** in 1.8 can't install this version. Download the .msi from this release's page. DNN Manager
  keeps using `Documents\DnnManager`, so your settings, projects, backups and logs are where they were.
- The .msi installs into `Program Files\DNN Manager`, next to a 1.8 installed with the earlier Setup
  (`Program Files\DnnManager`). Uninstall the old one in Windows' **Apps** settings if you want only this one.
- DNN Manager no longer installs updates itself: install each new release's package over this one.
- If DNN Manager started when you sign in, turn **Start DNN Manager when you sign in to your computer** on again in
  **Settings → General**.
- The installers aren't code-signed yet, so Windows and macOS ask before the first start. On macOS choose **Done**,
  then **System Settings → Privacy & Security → Open Anyway**.
- On macOS the Keychain may ask once to let DNN Manager use it: choose **Always Allow**. On Linux a keyring (GNOME
  Keyring or KWallet) must be running to save passwords.
